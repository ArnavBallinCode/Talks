How it works

Media, AI and control take different paths.

media (WebRTC)AI pathcontrol
  • ~1:45. Orange first: interpreter's browser publishes WHIP to MediaMTX; listeners pull WHEP. Interpreter audio never passes through Python.
  • Grey: FastAPI holds booth state over WebSockets, and MediaMTX asks it before accepting a publish.
  • Blue: AI workers in the FastAPI process read a copy of a channel (usually the floor) over RTSP, and push captions and synthetic speech over WebSockets. So AI audio does go through Python, the human path doesn't.
  • Transition: "It didn't start like this."
Engineering challenge 1 of 2

Getting Python out of the media path.

Problem

v1 relayed interpreter audio through Python (aiortc), and listeners played HLS, which buffers whole segments before playing.

Decision

Publish WHIP straight to MediaMTX, play back over WHEP, and keep FastAPI for coordination only.

Why

WebRTC plays packets as they arrive; Python stops being a bottleneck for every listener.

Trade-off

WebRTC needs a reachable UDP port for ICE, and each listener holds a connection to MediaMTX. HLS caches through a CDN more easily.

Evidence

The migration PRs below, and the old HLS config: 1 s segments with a 3-segment buffer. Delay hasn't been benchmarked yet.

  3. MAY 28 – JUN 5 · v3 · #81 #93 #117FastAPI + WHEP playbackaiortc, Flask and the HLS fallback removed

Engineering challenge 2 of 2

Big glossaries, small prompts.

Problem

Organisers upload thousands of terms ("FOSSASIA", "pull request"). Sending all of them with every caption segment makes LLM calls slower and costlier.

Decision

Per segment and language: keep terms that appear in the text, prefer booth over room over event entries, always keep priority ≥ 90, cap at 80.

Why

A bounded prompt keeps provider latency and token cost predictable, however large the glossary.

Trade-off

Exact and phrase matching can miss inflected forms. The local NLLB model ignores glossaries and persona entirely.

Evidence

A test with 10,000 matching terms stays at 80 entries and keeps the event loop responsive. tests/test_ai_interpretation.py · PR #888

  • Cost: pick per room, not per platform
  • Privacy: keep transcripts on your own server
  • Languages: no single provider covers every language well

      Backup · going live safely
      
Fast isn't enough. Live has to be safe.

      

        
1
One voice per channel
Two interpreters live at once means listeners hear both. MediaMTX replaces the old publisher, and the booth registry decides who's active.

        
30 s
Tickets, not open mics
Going live redeems a single-use ticket. It expires in 30 seconds and only opens that booth's path, for the active interpreter. Tickets live in memory, so this assumes one portal replica. Built by Sanket Kokate (#796).

        
0
Roles from the client
The browser never says who it is. Roles come from the server session, so a modified client can't promote itself.

      

    

    
  • Backup. Credit #796 to Sanket Kokate. Handoff is the one people remember.

  


  
  

    

      Backup · what I learned
      

        
Latency is an architecture decision.
No amount of frontend tuning fixes audio that takes the long way round.

        
Keep Python out of the interpreter's audio path.
Python coordinates. A media server moves the human audio; AI workers read a copy.

        
Small PRs, reviewed in the open.
